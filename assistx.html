AssistX

A role-based helpdesk system that brings employee requests, department assignments, and ticket resolution into one workflow.

Built with Python and FastAPI, a PostgreSQL database, and a React interface. Deployed using Docker for access from a central server on a local network.

01 / The problem

One place to manage internal requests.

Employee issues can involve different teams and follow different approval or resolution paths. AssistX organizes those requests into tickets, gives users role-specific views, and helps the responsible department track them through resolution.

The focus was to make everyday ticket handling straightforward while keeping access and actions appropriate to each user's role.

02 / What I built

From request to resolution.

Ticket lifecycle

Create, update, search, filter and track tickets across pending and completed work.

Role-based access

Different views and permissions for employees, resolvers, administrators and department leadership.

Department workflows

Route and manage requests according to department, category and responsibility.

Operational dashboard

Summarize ticket activity and provide a practical overview of outstanding work.

03 / How it works

A straightforward application flow.

The React frontend communicates with FastAPI endpoints. Requests are validated and handled by backend logic, while PostgreSQL stores the application data. JWT-based authentication supports role-aware access.

04 / Related AI prototype

Exploring complaint classification with LLMs.

Alongside the ticketing application, I developed a separate Python prototype that converts free-text complaints into structured ticket fields such as department, category, subcategory, priority and summary.

OpenAI implementation

Uses the OpenAI SDK to request structured outputs.

Local implementation

Uses Ollama with a Qwen model for local inference.

Scope: This classifier is a separate prototype. It is not presented here as a deployed AssistX feature.
